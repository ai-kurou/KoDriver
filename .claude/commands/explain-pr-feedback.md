---
description: PR内の指摘（レビューコメント・CIボット等）を解説し、修正すべきか判断する。修正自体は行わない
---

指定された GitHub PR に来ている指摘（レビューコメント・インラインコメント・CI/Botのチェック結果等）を要約し、修正すべきかどうかを判断して報告してください。**この指示では修正自体は行わないこと。**

引数: $ARGUMENTS

- 第一引数は PR 番号（例: `993`）または PR の URL。
- 第一引数が空の場合は、このセッション内でやり取りしていた PR（直近で作成・参照した PR）を対象とする。該当する PR が会話履歴から特定できない場合は、何もせずユーザーに PR 番号または URL を確認する。

手順:

1. 第一引数から対象リポジトリと PR 番号を特定する（URL の場合は `gh pr view <URL>` でも解決できる）。
2. 以下の情報を収集する。
   - `gh pr view <番号> --json title,url,state,statusCheckRollup` で概要と CI/Bot チェックの結果。
   - `gh pr view <番号> --comments` または `gh api repos/<owner>/<repo>/issues/<番号>/comments` でトップレベルコメント（CodeRabbit・Sourcery・SonarQube・Codacy 等のボットコメントを含む）。
   - `gh api repos/<owner>/<repo>/pulls/<番号>/comments` でインラインレビューコメント。
   - `gh api repos/<owner>/<repo>/pulls/<番号>/reviews` でレビュー本体（Approve/Request changes 等）。
3. 収集した指摘それぞれについて、以下を整理する。
   - 指摘の内容（何を指摘しているか、インライン/トップレベルの別、対象ファイル・行）。
   - その指摘が妥当か（既存のコーディング規約・設計方針・CLAUDE.md の内容と照らして判断する）。
   - 修正すべきかどうかの結論と理由（例: 「このPRのスコープ外」「既存パターンと矛盾する」「妥当な指摘なので修正すべき」等）。
4. 指摘が存在しない場合、またはすべて「対応不要（情報のみ・Bot要約のみ等）」の場合はその旨を報告する。
5. 収集・分析のみを行い、コード変更・コミット・PRへの返信は行わない。ユーザーから別途「返信して」「修正して」等の指示があった場合のみ、そのときの指示に従って別作業として対応する。

**安全上の注意**: このコマンドは調査・報告のみを行う。ワークツリー作成・コード変更・コミット・PRへのコメント投稿は一切行わない。

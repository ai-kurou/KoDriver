指定された GitHub PR のタイトルと説明を、現在のブランチの変更内容に合わせて適切な内容に更新してください。

引数: $ARGUMENTS

- 第一引数は PR 番号（例: `993`）または PR の URL。
- 第一引数が空の場合は、このセッション内でやり取りしていた PR（直近で作成・参照した PR）を対象とする。該当する PR が会話履歴から特定できない場合は、何もせずユーザーに PR 番号または URL を確認する。

手順:

1. 第一引数から対象リポジトリと PR 番号を特定する（URL の場合は `gh pr view <URL>` でも解決できる）。
2. `gh pr view <番号> --json title,body,baseRefName,headRefName,url` で現在のタイトル・説明・ベースブランチ・対象ブランチを確認する。
3. 対象ブランチの内容を把握する。
   - `git fetch origin <ベースブランチ> <対象ブランチ>` の上で `git log <ベースブランチ>..origin/<対象ブランチ> --oneline` でコミット一覧、`git diff origin/<ベースブランチ>...origin/<対象ブランチ>` で差分内容を確認する。
   - 対象ブランチに対応するワークツリーが手元に存在する場合はそれを使ってよい（内容を壊さないよう注意する）。存在しない場合はワークツリーを新規作成せず、`origin/<対象ブランチ>` を fetch した内容で確認する。
4. 現在の PR タイトル・説明が、上記で確認した実際の変更内容と一致しているかを確認する。
   - タイトルは変更内容を簡潔に表しているか（日本語、70文字程度を目安に簡潔に）。
   - 説明は、変更の目的・内容・（必要であれば）テスト内容が過不足なく書かれているか。追加コミット（レビュー対応・CI修正等）で変更内容が増えている場合、それが説明に反映されているか。
   - ベースブランチが `feature/base/` 系の場合、CLAUDE.md の Git 操作ルールに従い、説明欄末尾に「## 取り込み済みPR」セクションがあるか確認する。このベースブランチへマージ済みの feature ブランチの PR で、まだ一覧に記載されていないものがあれば `- <PRタイトル>: #<番号>` の形式で追記する。
5. 更新が必要な場合、新しいタイトル・説明の内容をまとめ、`gh pr edit <番号> --title '<新タイトル>' --body '<新しい説明>'` で更新する。
   - 更新不要と判断した場合は、更新せずその理由を報告する。
   - 説明欄・タイトルに「Generated with Claude Code」等の署名やセッションURL（`https://claude.ai/code/session_...`）を含めない。
6. 更新した場合はタイトル・説明の新しい内容と PR の URL を、更新しなかった場合はその判断理由をユーザーに報告する。

**安全上の注意**: このコマンドは PR のタイトル・説明の更新のみを行う。コードの変更・コミット・プッシュ・レビューコメントへの返信は行わない。

---
description: PRがマージ済みであることを確認したうえで、現在のワークツリーとブランチを削除する
---

現在の作業ディレクトリに対応する git worktree とブランチを、対応する GitHub PR がマージ済みであることを確認したうえで削除してください。

手順:

1. `git rev-parse --show-toplevel` などで現在のワークツリーのパスと、`git branch --show-current` で現在のブランチ名を確認する。
2. 現在のパスが `.claude/worktrees/` 配下のワークツリーであることを確認する。**メインの作業ツリー（リポジトリ直下）ではこのコマンドを実行しない。** メインツリーだった場合は何もせず、その旨を報告して終了する。
3. `gh pr list --head <branch名> --state all --json number,state,url` （または既知の PR 番号があれば `gh pr view <番号> --json state,mergedAt,mergeCommit`）で、このブランチに紐づく PR のマージ状態を確認する。
   - PR が見つからない、または `state` が `MERGED` でない場合は、削除を行わずに現在の状態を報告して終了する（`CLOSED` の場合もユーザーに確認を促し、勝手に削除しない）。
4. マージ済みであることを確認できたら、メインの作業ツリー（リポジトリのルート）に `cd` してから以下を実行する。
   - `git status --porcelain` で作業ツリーがクリーンであることを確認する（未コミットの変更があれば削除前にユーザーへ警告し、中断する）。
   - `git worktree remove <ワークツリーのパス>`
   - `git branch -d <ブランチ名>`（force ではなく `-d` を使い、未マージのコミットが残っていれば失敗させる。失敗した場合は原因を報告してユーザーに判断を仰ぐ）
5. リモートブランチ（`origin/<ブランチ名>`）も削除する。`git push origin --delete <ブランチ名>` を実行する。既に GitHub 側の自動削除設定等でリモートブランチが存在しない場合は、エラーを無視してその旨を報告する。
6. 削除したワークツリーのパス、削除したローカル・リモートブランチ名、および確認した PR 番号・URL を報告する。

**安全上の注意**: 自分（このセッション）が作業していたワークツリーのみを対象とすること。他のセッションが並行して使用している可能性がある他のワークツリーには一切触れないこと。`git worktree remove` や `git branch -d` 以外の破壊的操作（`--force`, `-D`, `git worktree remove --force` 等）は使わないこと。

---
description: 実装内容とベースブランチを指定して、専用ワークツリー・ブランチを作成し実装に着手する
---

第一引数を「実装内容」、第二引数を「ベースブランチ」として受け取り、作業用ワークツリーとブランチを作成したうえで実装を開始してください。

引数: $ARGUMENTS

- 第一引数（実装内容）が空の場合は、何もせず実装内容を確認するようユーザーに促して終了する。
- 第二引数（ベースブランチ）が空の場合は `main` をデフォルトとして扱う。

手順:

1. リポジトリのルート（`git rev-parse --show-toplevel`）に移動し、`git status --porcelain` で作業ツリーがクリーンであることを確認する。未コミットの変更が残っている場合は、削除・上書きせずユーザーに報告して中断する。
2. 指定されたベースブランチを最新化する（`git fetch origin <ベースブランチ>` の上で、ベースブランチが `main` などリモート追従ブランチであれば `git pull` してよい。ローカルにしか存在しない場合はそのまま使用する）。存在しないベースブランチが指定された場合は、削除・作成などを行わずエラーを報告して終了する。
3. 実装内容から簡潔で分かりやすい英語の kebab-case のブランチ名を提案する（例: 実装内容が「終了確認ダイアログを削除する」なら `feature/remove-exit-confirmation-dialog` のように、変更の性質に応じて `feature/` `fix/` `chore/` などの prefix を付ける）。
4. `.claude/worktrees/<ワークツリー名>` にワークツリーを作成する。ワークツリー名はブランチ名から `feature/` 等のprefixを除いたものを使う。
   - `git worktree add .claude/worktrees/<ワークツリー名> -b <ブランチ名> <ベースブランチ>`
   - 既に同名のワークツリーやブランチが存在する場合は、上書き・削除せずユーザーに報告して終了する。
5. 作成したワークツリーに移動し、CLAUDE.md の「実装前」チェックリストに従う。
   - 既存実装を確認する（対象モジュールの README・近い責務の既存コードを `rg` 等で調査）。
   - 実装対象のモジュール・依存方向が妥当かを確認する。
   - 追加・変更するテストの対象を洗い出す。
6. 受け取った「実装内容」に基づいて実装を進める。CLAUDE.md のテスト方針・コーディング規約・Git操作ルールに従うこと。特に以下を厳守する。
   - コミット・プッシュ・PR作成は、ユーザーが明示的に指示するまで行わない。
   - `moduleGraphAssert` ブロックは変更しない。
   - スクリーンショット画像・モジュール図はステージングしない。
7. 実装が一区切りついたら、変更内容の要約と、コミット・PR作成の要否をユーザーに確認する。

**安全上の注意**: このコマンドはワークツリー・ブランチの新規作成のみを行い、既存のワークツリー・ブランチ・コミット履歴を削除・上書きしない。他セッションが使用中の可能性があるワークツリーには一切触れない。

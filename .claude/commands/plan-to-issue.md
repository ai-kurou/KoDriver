受け取った「実装内容」について、コードは一切変更せずに調査・計画のみを行い、その結果を GitHub issue として起票（または既存issueの更新）してください。実装（コード変更・コミット・PR作成）は行いません。

引数: $ARGUMENTS

## 引数の解釈

引数は「実装内容（第一引数）」と「更新対象issueのURL（第二引数、任意）」からなる。

- 引数の末尾が `http://` または `https://` で始まるトークンの場合、それを第二引数（更新対象issueのURL）として切り出し、残りを第一引数（実装内容）とする。末尾がURLでなければ引数全体を第一引数として扱い、第二引数はなしとする。
- **第一引数が空の場合**: このコマンドを呼び出すまでの会話内容を「実装内容」として扱う。会話内で実装対象・背景・要望などが具体的に述べられていない場合のみ、何もせずユーザーに実装内容を確認するよう促して終了する。
- **第一引数が指定されている場合**: その内容をそのまま「実装内容」として扱う（プレフィックスやオプションのパースは不要）。
- **第二引数（URL）が指定されている場合**: `gh issue view <URL>` 等で該当issueの存在を確認し、issue作成フェーズでは新規作成ではなく更新を行う（詳細は後述）。
- **第二引数が指定されていない場合**: 新規issueを作成する。

## 調査・計画フェーズ

1. `git rev-parse --show-toplevel` でリポジトリのルートを確認し、そこを起点に調査する。ファイルの編集・作成、`git commit` 等の変更は一切行わない（読み取り専用のツール——`Read` / `Grep` / `rg` 等のみを使う）。
2. CLAUDE.md の「実装前の類似コード確認」に従い、対象モジュール・近い責務の既存コードを調査する。
   - 対象モジュールの `README.md`
   - 同じ種類の画面・UseCase・Repository・DataSource・テストの既存実装
   - 命名・粒度・責務分割・テストスタイルが既存パターンとどう一致するか
3. 調査結果をもとに、以下を明確化する。
   - 背景・目的（なぜこの変更が必要か。「改善したい」等の抽象的表現ではなく具体的な理由）
   - 対象モジュール・ファイル（優先順位付き）
   - 現状の挙動（バグの場合は再現手順も）
   - 期待する挙動
   - 参考にすべき類似実装（あれば、ファイル名・クラス名で具体的に）
   - 実装手順案（プランモード相当。既存パターンに沿った具体的なステップ）
   - 受け入れ条件（機械的に判断できる箇条書き）
   - スコープ外・触ってほしくない箇所（あれば）
   - 特に見てほしいテスト観点（あれば）
   - 参考URL・関連issue/PR（あれば）
4. 内容が実装内容の説明だけでは調査しきれない・複数の解釈がありうる場合は、`AskUserQuestion` でユーザーに確認してから issue 本文を確定させる。

## issue作成・更新フェーズ

5. `.github/ISSUE_TEMPLATE/claude-implementation.yml` の各フィールド（背景・目的、対象モジュール・ファイル、現状の挙動、期待する挙動、参考にすべき類似実装、実装手順案、受け入れ条件、スコープ外・触ってほしくない箇所、特に見てほしいテスト観点、参考URL・関連issue/PR）に沿って本文を組み立てる。
6. 第二引数（更新対象issueのURL）が**ない場合**（新規作成）:
   - `gh issue create --title "[Claude実装] <実装内容から要約した簡潔なタイトル>" --label claude-implementable --body <組み立てた本文>` で起票する。タイトル・本文は日本語で書き、署名やセッションURLは含めない。
7. 第二引数（更新対象issueのURL）が**ある場合**（既存issue更新）:
   - 更新前に `gh issue view <URL>` で現在のタイトル・本文・状態（open/closed）を確認する。
   - 本文は既存内容を残さず、今回組み立てた本文で**丸ごと置き換える**（`gh issue edit <URL> --body <組み立てた本文>`）。タイトルも実装内容の変化に応じて必要なら `--title` で更新する。
   - issueがcloseされている場合は、上書きしてよいか・再オープンするかをユーザーに確認してから進める（無断でreopenしない）。
8. 起票・更新した issue の URL をユーザーに報告する。あわせて、背景・目的と実装手順案の要点を簡潔にまとめて伝える。

**安全上の注意**: このコマンドは調査・issue起票・第二引数で指定された既存issueの本文更新のみを行う。ファイルの編集・作成、`git add`/`git commit`/`git push`、ワークツリー・ブランチの作成、PR作成は一切行わない。第二引数で指定されていない他のissueの編集・クローズは行わない。

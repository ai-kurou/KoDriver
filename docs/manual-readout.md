# 手動読み上げ

「手動」タブでは、現在のテレメトリから読み上げたい項目をセットとして保存し、必要なときにセット単位で読み上げる。画面は `:feature:manual-readout-list` と `:feature:manual-readout-detail` に分かれ、両者は `app:shared` の詳細スロットを通じて接続する。項目の対応状況は domain の `manualReadoutItemKeys(simulatorId)` が正である。

## 使い方

1. 「セットを追加」で空のセットを作る。
2. セット行をタップして詳細を開き、「＋ 項目を追加」から読み上げる項目を選ぶ。
3. 必要に応じて項目の順序・文言・セット名を編集し、試聴する。
4. 一覧に戻り、行右端の ▶ または割り当てた Windows ホットキーで読み上げる。

セット行の他の部分をタップすると詳細を開く。長押しメニューから削除を選び、確認ダイアログで確定すると削除される。詳細の戻る操作で一覧に戻る。別タブへ移動して戻った場合は、選択中の詳細を維持する。選択中の「手動」タブを再タップすると一覧へ戻り、一覧表示中に再タップすると先頭へスクロールする。

## 対応項目

以下は項目ピッカーに表示される名前と順序。1セットにつき最大3項目を選択できる。同じ項目は重複選択できない。

| シミュレーター | エネルギー | タイヤ | ブレーキ | ラップ |
| --- | --- | --- | --- | --- |
| LMU | バーチャルエネルギー残量、エネルギーの残り周回数 | タイヤ摩耗、タイヤ温度、タイヤ摩耗の残り周回数 | ブレーキ残量、ブレーキ温度 | 自己ベストラップ |
| ACE | 残り燃料、残り燃料の周回数 | タイヤ温度 | — | 自己ベストラップ |
| GT7 | 残り燃料、残り燃料の周回数 | タイヤ温度 | — | 自己ベストラップ |

未知のシミュレーターIDには項目を提供しない。セットに対応項目が一つもない場合は固定文言「読み上げる項目がありません」を読む。

## 読み上げ

一覧の ▶ とホットキーは、シミュレーターIDとセットIDを含む `ManualReadoutRequest` を送る。値の取得・文言の組み立ては各シミュレーターの Narrator が行う。手動読み上げは自動読み上げスイッチに依存せず、自動警告の重複抑止・読み上げ済み状態も変更しない。

保存順に各項目の文を評価し、空欄を除いて「、」で連結した一つの読み上げイベントにする。値を取得できない項目は項目名付きの「<項目名>はデータがありません」として他の項目と連結する。LMU は選択した全項目がデータなしの場合に限り「データがありません」のみを読む。ACE と GT7 は項目ごとのデータなし文言を連結する。セット自体に対応項目がない場合の「読み上げる項目がありません」とは区別する。

セット読み上げは開始音を鳴らし、読み上げキュー設定にかかわらずキュー末尾へ追加する。テレメトリログとオーバーレイにも通常の読み上げイベントとして出力する。開始音・ログ等に用いるキーはシミュレーターごとの既存Narrator契約に従う。LMU は先頭の読み上げ対象項目に対応するキーを使い、ACE と GT7 はセット内容にかかわらず「残り燃料」の固定キーを使う。セットIDが見つからない依頼は読み上げない。

### 現在値の扱い

- **LMU**: バーチャルエネルギー残量は単一のテレメトリ値を使う。タイヤ摩耗・ブレーキ残量は4輪の値から代表値を作り、ブレーキ残量は最小の `remainingPercent`、温度は4輪の最高値を使う。エネルギーとタイヤ摩耗の残り周回数は蓄積済みの周回消費量から整数周を推定する。自己ベストラップはセッションのベストラップタイムを読む。
- **ACE**: 残り燃料は残量を整数％に丸め、残り燃料の周回数は燃料追跡値の整数部を使う。自己ベストラップとタイヤ温度にも対応する。温度は4輪の有効なカーカス温度の最高値を整数℃に丸める。
- **GT7**: 残り燃料はテレメトリの残量から整数％を計算し、残り燃料の周回数は平均消費から整数周を推定する。タイヤ温度は4輪の有限値の最高値を整数℃に丸め、自己ベストラップはテレメトリの確定したベストラップタイムを読む。
- 現在値を使う項目は、原則として未受信・受信から5秒を超過・値が利用不能ならデータなしとする。自己ベストラップは各シミュレーターの値の確定条件に従う。LMUの摩耗・ブレーキ残量は 0〜100% の値をそのまま割合として扱い、二重に百分率変換しない。
- LMU と GT7 は、残り周回数が0なら項目固有の「残り1周未満」文言を使う。ACE は燃料追跡値の整数部を文言へ挿入するため、0.1〜0.9周は「0周」と読み上げ、燃料追跡値が0以下ならデータなしとして扱う。編集文言が空欄なら、その項目からは何も読まない。
- 自動の警告しきい値、ヒステリシス、重複抑止は手動読み上げに適用しない。LMU/ACE の温度・摩耗警告の状態や各 Narrator の自動判定状態も変更しない。

## セットと文言の編集

- 新規セットは空で作成され、一覧末尾へ追加される。セットの並べ替えやセット数上限は設けていない。
- 項目はカテゴリ別に選択し、選択時に末尾へ加わる。詳細ではドラッグで順序を変更できる。セット名は最大20文字、重複可で、未設定なら一覧の「セット N」を表示する。セット名は読み上げ文に含めない。
- 項目ごとに文言を編集する。未編集なら項目の既定文言を使う。入力は前後の空白を除去して最大30文字で保存する。空欄は読み上げない。リセットで既定文言に戻す。項目を一度選んで文言を変更した後に選択解除しても、保存した文言は保持される。
- 対応するプレースホルダーは `{percent}`、`{laps}`、`{celsius}`、`{laptime}`。入力欄からカーソル位置へ挿入でき、選択文字列があれば置換する。文字数上限を超える挿入は行わない。未知のプレースホルダーは警告するが、読み上げ文から自動削除はしない。
- 試聴プレビューは保存順に空欄を除いて「、」でつなぐ。サンプル値は割合50%、温度90℃（ブレーキ温度は500℃）、周回数はLMU/GT7が3周、ACEが5周、ラップタイム1分23秒456を使う。試聴はセット読み上げの値取得を行わず、文言確認用のプレビューである。先頭項目の開始音を使い、再押下・ペイン離脱で停止する。TTSが利用できない、またはプレビューが空なら試聴できない。

## 保存とホットキー

セット（ID、名前、項目順、項目別文言、ホットキー設定）はシミュレーター単位で端末ローカルに保存する。保存ファイルは `manual_readout_set_preferences_${simulator.id}.pb`。WindowsとAndroidの間で設定は同期しない。デバッグ用ホットキーの既存保存先 `lmu_windows_readout_hotkey_preferences.pb` は別設定である。

Windows デスクトップのみセットごとにホットキーを設定できる。数字0〜9または英字A〜Zと、Ctrl+Alt+Shift（初期値）、Ctrl+Alt、Ctrl+Shift、Alt+Shift のいずれかを組み合わせる。Fキーは使わない。キー未割り当ても可能で、修飾キーはその場合も保存できる。Android、macOS、Linux ではホットキーの設定カードと一覧チップを表示しない。

OSのグローバルホットキーはシミュレーター間で共有されるため、他セットとの競合は全シミュレーターを対象に「修飾キー＋キー」の組み合わせで判定する。共通のデバッグ用ホットキーとの競合は Ctrl+Alt+Shift の場合に判定する。詳細画面には競合相手（シミュレーター名・セット名またはセット番号）と登録状態を表示する。競合・登録失敗時は再試行できる。未割り当てまたは非対応環境では登録状態を表示しない。

## 実装上の境界

- 一覧 feature はセット一覧・依頼送信・list/detail 切り替えを担当し、読み上げ内容を作らない。
- 詳細 feature はセット編集と試聴を担当し、Narrator の読み上げ判定を持たない。
- `app:shared` が一覧の詳細スロットへ詳細画面を渡す。feature 間の直接依存は作らない。
- セット読み上げ依頼の経路は既存のF9自動読み上げ経路と分け、自動読み上げの挙動を保つ。

## 主な実装箇所

- 項目キー・項目名・既定文言: `core/domain/.../model/ManualReadoutItems.kt`
- 1セットの項目数上限や共通既定値: `core/domain/.../model/ManualReadoutDefaults.kt`
- 一覧・ナビゲーション: `feature/manual-readout-list/`
- 詳細・項目編集・試聴・ホットキー: `feature/manual-readout-detail/`
- セットの永続化: `core/data/.../ManualReadoutSetPreferences*`
- シミュレーター別の値取得と読み上げ: `core/domain/.../usecase/Determine*ReadoutUseCase.kt` の各 Narrator 実装
- 共有画面への接続: `app/shared/`

項目を追加・変更するときは、項目候補と表示名、既定文言・プレースホルダー、Narratorでの値取得と欠損時の扱い、試聴値・開始音/ログ用キー、関連するテストを一緒に更新する。このページと詳細は実装と `manualReadoutItemKeys(simulatorId)` を照合して保つ。

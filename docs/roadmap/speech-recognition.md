# 音声認識の常時表示 ロードマップ

ベースブランチ `feature/base/speech-recognition` で少しずつ実装する「音声認識の常時表示（マイクの有効/無効・音量・認識結果）」の仕様と進捗。
`/cleanup-worktree` が、マージ済みPRのベースブランチ（`feature/base/*`）に対応するこのファイルを読み、次の実装候補を提示する。

- ファイル先頭のフロントマターに `base-branch:` を持つロードマップだけが対象になる。
- PR をマージしたら、同じ PR または直後の PR でチェックを付ける（実装済みの履歴は `git log main..<base-branch>` でも確認できる）。
- 実装しながら仕様が変わったら、このファイルを同じ PR で更新する。

## 背景

現在、音声認識の確認用カード（`feature/main` の `SpeechRecognitionCard`）は「その他」と各シミュレーターの `DebugStateDetail` にしか出ない。音声認識はどの画面からも使われるため、ユーザーが常に状態を確認できるようにする。

## 仕様（合意済み）

- 表示する情報: 「マイクの有効/無効」「入力音量」「認識した音声（スラッシュ区切りの候補）」。
- 常時表示するのは、リング型の小さなチップ（約44dp）だけ。マイクアイコンの周囲のリングが音量に応じて伸びる。
- 位置: アプリ共通シェル（`AppScreen` の外側 `Box`、`SnackbarHost` と同じ階層）の**右下**に重ねる。スマホは下部ナビバーの直上、広い画面は右下の隅。見た目と位置はスマホ・デスクトップで共通。右下で一旦様子を見る（TopAppBar の actions や上部バナーとの重なりを避けるため）。TopAppBar の有無に依存しない。
- チップの状態: ON（待機中）/ ON（コマンド待ち、色を強調）/ OFF（斜線・グレー、リングなし）/ エラー（権限なし・マイク不可・認識不可・無音を区別）。OFF のときは音量リングを出さない。
- タップで詳細を開く。スマホはボトムシート、デスクトップはポップオーバー。中身は共通の Composable にし、外枠だけ切り替える。
  - 有効/無効スイッチ、音量ゲージ（大きめ）、認識結果（新しい順、スラッシュ区切り、最大5件）、入力デバイス選択（デスクトップのみ）。
- 認識結果は常時表示せず、詳細を開いたときだけ見せる。
- 音量リングは滑らかなバーにせず、段階表示にして再コンポーズの負荷を抑える。
- 状態は既存の `SpeechRecognitionUiState` / `SpeechRecognitionViewModel` を共有する（聞き取りの管理は `AppScreen` が一度だけ行っている）。ドメインの新規追加は不要。
- `DebugStateDetail` の `SpeechRecognitionCard` は変更せず、このロードマップの対象外とする。「その他」の既存カードは残す前提で、整理するかは後で決める。

## 実装済み

- 右下の共通チップ（マイクの有効/無効とエラー状態のみ。OFF・ON待機中・ONコマンド待ち・エラーの4状態）を `AppScreen` に重ねて表示した: #3026
- チップの縁に、聞き取り中の音量を5段階のリングで表示した（OFF・エラーでは出さない）: #3030
- チップのタップで詳細を開く（スマホ: ボトムシート / 広い画面: ポップオーバー）。有効/無効スイッチ・音量ゲージ・認識結果・入力デバイス選択（デスクトップのみ）を並べる: #3032
- 右下に置く他の要素がチップに重ならないよう避けた（手動読み上げの追加ボタンはチップの上へ、Snackbar はチップの幅だけ右端を空ける）: #3034
